# Virtual Columns & Sales Pipeline

Implementation of `add_virtual_column` for `pandas.DataFrame` (Part 1), a data-cleaning and regional revenue aggregation pipeline for `sales.csv` (Part 2), and an automated test suite (Part 3).

## Project Structure

- `solution.py` — `add_virtual_column` implementation (Part 1).
- `pipeline.py` — data cleaning and regional revenue aggregation pipeline for `sales.csv` (Part 2).
- `revenue_by_region.csv` — aggregated regional revenue generated by `pipeline.py` (Part 2).
- `test_virtual_column.py` — provided sample unit tests.
- `test_pipeline_and_virtual_column.py` — extended unit and integration tests for Parts 1 & 2 (Part 3).
- `sales.csv` — original raw input dataset.
- `requirements.txt` — Python dependencies (`pandas`, `pytest`).

## Setup & Execution

1. **Create a virtual environment and install dependencies:**
   ```bash
   python -m venv .venv
   source .venv/bin/activate  # On Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   ```
2. **Run the data pipeline (generates `revenue_by_region.csv`):**
   ```bash
   python pipeline.py
   ```
3. **Run all tests with a single command:**
   ```bash
   pytest -v
   ```

## How It Works & Edge Cases

### Part 1: `add_virtual_column` (`solution.py`)

- **Validation:** Enforces `^[A-Za-z_]+$` on `new_column` and all existing `df.columns` labels, and verifies that every referenced column exists in `df`.
- **Safe AST Evaluation:** Uses `ast.parse(..., mode="eval")` instead of `eval()`, allowing only column names (`ast.Name`) and `+`, `-`, `*` (`ast.BinOp`). Supports multi-operator expressions (e.g., `quantity * unit_price - discount`), standard operator precedence, parentheses, and arbitrary whitespace.
- **Immutability & Error Handling:** Works on `df.copy()` without mutating the input. Any invalid label, unknown column, unsupported operator (`/`, `**`, `%`, numeric literals, unary signs, function calls), non-string input, or incompatible column dtype (`TypeError`) returns an empty `pandas.DataFrame([])`. Empty DataFrames with valid column names preserve their schema and receive the new empty column.

### Part 2: Sales Pipeline (`pipeline.py`)

- Reads `sales.csv` as raw strings (`dtype=str`, `keep_default_na=False`), cleans structural and field-level anomalies without dropping recoverable orders, computes `revenue` via `add_virtual_column(df, "quantity * unit_price - discount", "revenue")`, and exports rounded regional totals to `revenue_by_region.csv`.

## Data Quality Issues Found in `sales.csv`

`sales.csv` has **1,508** lines (1 header + 1,507 data/artifact rows):

| # | Issue | Rows Affected | Handling |
|---|-------|---------------|----------|
| 1 | **Spaces/mixed case in headers** (`Order ID`, `Quantity `, `Unit Price`, `Order Date`) | All rows (schema) | Normalized to `snake_case` (`order_id`, `quantity`, `unit_price`, `order_date`) to match `[A-Za-z_]+`. |
| 2 | **Repeated header row mid-file** (line 753) | 1 row | Filtered out rows where `order_id == "Order ID"`. |
| 3 | **Footer `TOTAL` summary row** (line 1508) | 1 row | Filtered out rows where `order_id == "TOTAL"`. |
| 4 | **Exact duplicate rows** (`SO-10305`, `SO-10822`, `SO-10966`, `SO-11240`, `SO-11405`) | 5 duplicate rows (10 total) | Removed with `drop_duplicates()`, leaving 1,500 unique orders (`SO-10001`–`SO-11500`). |
| 5 | **Whitespace & inconsistent casing in `Region`** (e.g., `' North'`, `'east  '`, `'EAST'`, `'central'`) | 15 rows (8 whitespace, 10 casing) | Applied `.str.strip().str.title()` (`Central`, `East`, `North`, `South`, `West`). |
| 6 | **Space thousands separators in `Quantity`** (`"1 762"`, `"1 745"`, `"1 371"`, `"1 427"`) | 4 rows (`SO-10251`, `SO-10734`, `SO-11088`, `SO-11312`) | Stripped internal whitespace (`\s+`) before casting to `int`. |
| 7 | **Negative `Quantity` values** (`-2` to `-5`) | 6 rows (`SO-10421`, `SO-10515`, `SO-10779`, `SO-11011`, `SO-11289`, `SO-11445`) | Kept as negative integers (treated as returns/credit notes). |
| 8 | **Comma decimal separators in `Unit Price`** (e.g., `"59,00"`, `"39,90"`, `"249,00"`) | 7 rows (`SO-10137`, `SO-10402`, `SO-10688`, `SO-10911`, `SO-11203`, `SO-11377`, `SO-11460`) | Replaced `,` with `.` before converting to `float`. |
| 9 | **Missing `Unit Price` values** | 4 rows (`SO-10610`, `SO-11099`, `SO-11350`, `SO-11477`) | Imputed from each product's fixed catalog price (`Printer paper` = `21.00`, `Keyboard` = `89.00`). |
| 10 | **Empty `Discount` cells** | 959 rows (of 1,500 unique) | Filled with `0.0` per specification. |

## Assumptions & Decisions

- **Fixed catalog unit prices:** Every product has a single invariant unit price across the dataset (verified via `SO-11477`, where `37 * 89.00 * 0.05 = 164.65` matches the recorded 5% discount), allowing exact imputation of missing prices.
- **Negative quantities as returns:** Lines with negative quantities have valid sequential IDs, dates, and unit prices; they are retained so regional totals reflect net revenue.
- **Space-separated quantities as bulk orders:** Values like `"1 762"` represent thousands-separated bulk quantities (consistent with European comma decimals and matching the raw `TOTAL` quantity `37,150`).
- **Output schema:** `revenue_by_region.csv` uses two columns (`region,revenue`), sorted alphabetically by `region` with values rounded to 2 decimal places (`0.01`).
